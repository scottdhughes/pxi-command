# PXI Research Lab

This folder is an offline evidence gate for PXI model research. It does not
modify Cloudflare, D1, KV model objects, production weights, public signals, or
the frontend.

## What it does

- validates a versioned feature-snapshot contract;
- rejects features whose names indicate obvious target leakage;
- verifies each feature row was available by its decision date;
- derives 7- and 30-calendar-day forward benchmark returns;
- creates expanding walk-forward slices;
- purges training rows whose forward target overlaps the test window;
- compares a train-only linear calibration of the fixed PXI score with ridge;
- reports RMSE, rank IC, direction accuracy with a Wilson interval, and a
  cost-adjusted per-signal directional edge proxy;
- diagnoses missing features, high pairwise correlation, and PCA concentration;
- emits an explicit `GO` or `NO_GO` governance result.

The directional edge proxy is not a portfolio simulation. Horizons overlap, so
the report intentionally does not claim CAGR, Sharpe, or an executable return.

## Reproducible public smoke test

```bash
npm run research:test
npm run research:snapshot
npm run research:run
```

The public snapshot combines PXI's public 365-day history with exact-date FRED
S&P 500 closes. It sets `point_in_time_guarantee=false`, so its result must be
`NO_GO` regardless of its apparent performance. Its purpose is to exercise the
pipeline end to end.

Generated inputs and reports are written below `research/out/` and ignored by
Git.

## Production-quality snapshot requirements

A candidate snapshot must conform to `snapshot.schema.json` and set
`point_in_time_guarantee=true` only when all of the following are demonstrable:

1. Each feature has both observation time and first-availability time.
2. Economic revisions are stored as vintages rather than overwriting history.
3. The feature dictionary and transformation code have immutable versions.
4. Each row contains only data available by the decision timestamp.
5. Benchmark prices and corporate-action treatment are documented.
6. A snapshot can be regenerated byte-for-byte from immutable source artifacts.

Production writes now also capture an append-only decision snapshot in D1. Each
snapshot preserves the exact numeric feature vector, per-feature observation
date and source, benchmark close, feature version, server availability time,
and capture source. The authenticated export endpoint is:

```text
GET /api/export/research-snapshot?limit=1000
```

Only snapshots captured at or before the end of their decision date and with
complete provenance are exported. Historical mutable rows are deliberately not
backfilled or relabeled as point-in-time safe. The dataset therefore begins at
the deployment of this capture contract and needs to accumulate before the
minimum walk-forward sample gate can pass.

## Gate interpretation

`GO` means only that the configured research gates passed on a properly
versioned snapshot. It does not authorize a production deployment. Any promoted
model still needs an immutable model record, independent review, shadow-mode
monitoring, and an explicit deployment decision.
